# V3.3.1 工程核算审计：甲烷化 `ch4_v33_t3`（开发集）

2026-11-14。对应 `docs/V3_3_PERFORMANCE_ROADMAP.md` 的 Phase 0 和 Phase 1。甲烷化属于开发集，这里的审计和修改不涉及检验集。

## 1 先核对边界：是不是在比同一个工厂

D5.9 原文（评估侧文件，不进 agent 工作区）逐项对照：

| 项目 | 模型 `ch4_v33_t3` | D5.9 参考值的边界 | 依据 |
|---|---|---|---|
| CO2 压缩到反应压力 | 计入（1 → 21 bar） | **在甲烷化单元内** | p.39：甲烷化单元电耗改进项写明 "A CO2 compression is needed only if the H2 is produced at reaction pressure"；Fig. 5-2 第一步优化 "(only CO2 compression)" 属于 CAPEX_Meth |
| CO2 捕集 / 供应 | 不计（外购 CO2） | 不在边界内（表 4-2 单列 CO2-Source 1.0 kWh/m³） | p.39 表 4-2；p.69 |
| 两级甲烷化反应器、冷却、分水、干燥 | 计入 | 在甲烷化单元内 | p.10–11 流程描述 |
| SNG 精制 | 计入（单独的膜/吸附分离器） | D5.9 用第二级精制反应器达到入网品质，没有单独分离 | p.10 "A second polishing reactor completed the methanation reaction" |
| 并网压缩（63 bar） | 不计（产品 20 bar 出界区） | 不在边界内，单列 0.10 kWh/m³ | p.69 表 5-2 |
| 能源口径 | 外购电 ÷ 0.38 | 0.29 kWh/m³ SNG ÷ 0.38 = 3.84 GJ/t | p.69–70 |

结论：Notion 第 41 页推测的"CO2 压缩可能在参考边界外"不成立。CO2 压缩在 D5.9 的甲烷化单元内，模型和参考值比的是同一个边界，能耗超标要从模型本身找原因。留出值和容差不变。

## 3 投资账（USD/(t/y)，产能 57 120 t/y）

| 单元 | 投资 | 计算方式 |
|---|---:|---|
| 甲烷化反应器 | 742.9 | 全厂 880 USD/kW 的 28 % 份额，再按（含循环的进料 / 化学计量进料）^0.6 和催化剂量 ^0.3 放大 |
| SNG 精制分离器 | 158.3 | 份额 10 %，按净气量放大 |
| 进出料换热器 | 106.8 | 份额 |
| 其余 9 个单元 | 402.2 | 份额或按压缩功 |
| **合计** | **1410** | 留出值 684（479–1026） |

- **确认的错误：重复放大。** 880 USD/kW 是整厂的单位投资，已经包含原设计的循环。反应器份额又按含循环的流量放大了一次：份额应为 24.4 M USD，模型算成 42.4 M USD。
- **不是公式错误、但缺少依据的：** 880 USD/kW 取自 eFuel Alliance 报告表 88，模型没有记录这个数对应的装置规模，直接当作自己 99 MW 规模的价格。来源本身属于 agent 的选择，这里不改，但 V3.3.1 要求必须写明来源装置的规模和规模指数。
- 去掉重复放大后，按同一来源算是 1282 USD/(t/y)，仍超出容差。剩下的差距来自来源选择和规模换算，要看新版本的运行结果。

## 4 修改（V3.3.1，按单元类型写成通用规则）

| 修改 | 内容 | 对应的错误 |
|---|---|---|
| `unitops.cooling_utility` | 按物理量计算冷却用电：冷却水按 10 K 温升、3 bar 循环压升、冷却塔气水比 1、风机 200 Pa 计，约为负荷的 1.6 %（COP 约 61）；空冷约 1.9 %；冷冻按卡诺 COP × 0.5 | COP = 10 的假设 |
| `unitops.separator_energy` | 由各出口物流的压力算分离能耗：只有需要再压缩或抽真空的出口才耗电；低于进料压力离开的出口释放的压力㶲用于驱动分离 | 带进料压缩的单位体积电耗用在已加压的进料上 |
| `unitops.plant_cost_share`、`energy_ledger`、`capex_ledger` | 整厂单位投资按固定份额分摊；逐单元能耗账和投资账 | 份额被循环流量重复放大 |
| 物理门控（ledger 检查，V3.3.1 起） | 每个单元标 `boundary_role`；冷却单元标 `cooling_medium`，外购能耗不得超过冷却水 3 %、空冷 4 % 的负荷（除以 0.30 的一次能源效率下限）；分离器的外购能耗要写明 `energy_method`，引用文献系数时必须给出来源的进料压力，低于本单元进料压力一半的拒收；投资要有 `capex_basis`（方法、年份、是否已含安装），已含安装的不得再乘安装系数，按份额分摊的不得超过份额、份额合计不超过 1，并须给出来源装置的投资、规模和规模指数 | 以上三处 |
| 分离器物理检查（所有版本） | 分离出口给出压力时，泄压释放的压力㶲计入可用功 | 原来压力驱动的分离被当成零能耗，只能靠文献证据过关，促使 agent 去找单位电耗系数 |
| `check_model` 输出 | 写出参考工厂的 `energy_ledger.csv`、`capex_ledger.csv`，要求 agent 在报告中解释占比超过 10 % 的每一行 | 账目可追溯 |
| 评估侧 | `evaluate_builds.py` 在每次构建的记录里加入两张账；评分和判定不变 | |
| 版本号 | 建模框架 `V3.3.1-engineering-ledger`；单元库 UO-1.1（原文件头写的 V4 已更正为 UO-1.0，随 V3.3 发布） | 版本号混淆 |

这些规则按单元类型写成，对任何反应都适用，不含甲烷化或 D5.9 的任何数值。留出值和容差不变。

## 5 回放测试（`tests_v3/validate_v331.py`）

- 新函数逐项和手算对照：冷却水 1.63 %（手算 1.63 %），空冷 1.87 %，零下 10 °C 冷冻 COP 2.44（卡诺 × 0.5 为 2.58，再加冷凝器的冷却水），分离器泄压不耗电、再压缩等于 `compressor()`、抽真空计入。
- 用新门控回放 `ch4_v33_t3`：V3.3 门控下通过，V3.3.1 的 ledger 检查拒收（4 条）。即使补上字段如实申报，COP 10 的冷却（cooling_utility）和来自常压来源的分离电耗（separation_pressure）仍被拒收；反应器投资超出份额被拒收（capital_double_count）；份额分摊没写来源装置规模也被拒收（capital_scaling）。
- 把这三处按 UO-1.1 重算后，全部检查通过。**诊断值**（同一个旧模型，只重算这三处，不是新的建模结果）：外购能耗 7.15 → 2.63 GJ/t（冷却 1.78 → 0.29，分离 3.09 → 0.06），进入留出容差；投资 1410 → 1282 USD/(t/y)，仍超出。
- 全部回归测试通过：`validate_unitops`、`validate_v3`、`validate_v33`、`validate_v331`、`validate_evaluation`、`validate_blind`、`physics_gate_validate`。
