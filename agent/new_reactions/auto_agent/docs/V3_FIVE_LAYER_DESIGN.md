# 建模模式 V3：按五层决策架构落地（2026-11-13）

依据：Notion 40「五层决策架构」（GPT 提案）、甲烷化 V2 三次建模结果（`evaluation/CH4_AI_BUILD_RESULT.md`）、导师 11-11 要求。

## 1 对 Notion 40 提案的判断

可以用，作为 V3 的组织框架。五层基本是对现有资产的重新分组：

- Layer 1（证据）对应检索、下载、OCR、抽取、归一化；
- Layer 2（决策）对应旧 Layer B 和 DISCOVER；
- Layer 3（构建）对应 Build Mode；
- Layer 4（执行与验证）对应物理门控、`evaluate_builds`、留出审查。

这些已经有了。真正缺的是 **Layer 5（决策反馈）**：V2 建完模型、过了门控就结束，模型里自设的假设对结果影响有多大，没有回头去查。甲烷化 b2、b3 多算能耗，根源正是一个自设假设（H2 在 1 bar 进入装置）。

提案里有三点需要收紧后才能用：

1. **反馈只能用内部信号，不能用留出 TEA。** 如果 Layer 5 读到留出对照的结果再去改模型，外部验证就变成了校准。V3 的反馈只来自物理门控、假设敏感性和独立审查，`audit_holdout` 加一条检查，确认 agent 工作区里没有出现评估端的输出。
2. **Critic 不能自审。** 提案把独立 LLM Critic 列为可选。V3 加入 Critic，但它只看 agent 交出的产物（流程、设计基准、单元表），不看 agent 的推理过程。它只按固定的通用清单提问题，不给数字；agent 逐条修改或说明理由，全部记录。
3. **Phase A 审计大部分已经做完。** PDH 和甲烷化两轮已经查清了哪些由 agent 决定、哪些固定（见 `build_mode.py` 文件头），所以不再单独做一轮审计，直接改代码。

## 2 V3 相对 V2 的改动（按层）

| 层 | V3 新增 | 针对的问题 |
|---|---|---|
| 1 证据 | `basis.json` 设计基准：装置边界、每股进料的温度/压力/纯度、产品规格、产能、公用工程和价格。每项要么给出证据（论文与位置），要么标为假设并给出范围 | 甲烷化 H2 进料压力是 agent 默认的 1 bar，既没有出处，也没有给范围 |
| 2 决策 | `record_decision` 工具：机理、速率式、反应器、分离技术、界区等关键选择，各自写明备选方案、选择理由和证据，存入 `decisions.jsonl` | 让每个选择都能追溯 |
| 3 构建 | 保持先画流程再算账；流程和模型都读 `basis.json`，不能在代码里另设一套边界条件。有原子尺度证据的反应（氨分解）加原子尺度一层（见第 3 节） | 边界条件统一 |
| 4 验证 | 物理门控加上限：①压缩功 ≤ 2.5 倍等温最小功；②放热反应器的外购预热必须少于可回收反应热的 20%，否则要在 `basis.json` 中给出证据；③单元投资按设备类型做量级检查（例如压缩机 200–8000 USD/kW 轴功，加热炉 100–3000 USD/kW）；④边界进料状态必须与 `basis.json` 一致 | 甲烷化多算能耗；b1 投资高 46 倍 |
| 5 反馈 | `check_model` 通过后自动做假设敏感性：`basis.json` 和 `sources.csv` 里的每个假设，在各自的范围内单独变动。只要有一项使参考成本或能耗变化超过 10%，就记为一条"证据欠账"。agent 在 `finish` 之前必须逐条处理：补证据缩小范围，或者保留并在报告中列为主要不确定性。之后由 Critic 审一轮 | 让 H2 进料压力这类假设被自动发现，并要求补证据 |

保持不变的：留出隔离和审查、预注册、三次独立建模和一致性规则、账本。

## 3 氨分解：原子 → 实验室 → 工厂全链

NCE 的原子层（Wang & Abild-Pedersen 2021 S1 数据：对 E_N 的标度关系 → 稳态微观动力学 → TOF → 活性金属量和床层 → 工厂成本 → 反推描述符窗口）是手工模型。按导师的规则，它是隐藏参照，不给 agent 看。在 AI 建模框架里，氨分解的三尺度链路这样接：

- **固定的通用基础设施**：`mkm_solver.py`，一个不含任何反应数据的平均场稳态微观动力学求解器。它的地位和 scipy 一样。
- **agent 自己决定并给出出处**：
  - 描述符（例如 N 结合能）、基元步骤、标度关系和 BEP 系数、各金属的描述符值；
  - 写成 `atomic.py`，包含 `logtof(D, T, p)` 和 `record_from_descriptor(D, 金属价)`，后者把描述符换成工厂模型的输入；
  - `check_atomic` 检查热力学方向（平衡两侧的净速率符号）、火山形状、出处，以及换算出的记录能否通过工厂模型的物理门控。
- **三个最优**：`run_three_optima` 输出
  - 原子最优：工厂反应条件下 TOF 最高的描述符；
  - 实验室最优：实测速率最高的记录；
  - 工业最优：工厂成本最低的记录，以及计入金属价格后成本最低的描述符；
  - 每条实验记录反推出的有效描述符 D_eff；
  - 反推设计：参考成本下降 5% 和 10% 时，描述符需要落在什么窗口；
  - 三者之间的分歧次数，写明分母。

  这和 NCE 正文里氨合成的"原子 → 实验室 → 工厂"结构一一对应。
- **验证**：
  - 工厂层对照留出的氨分解 TEA；
  - 原子层对照留出的已发表分解火山（最优描述符位置，容差 ±0.2 eV）；
  - NCE 手工原子模型在分解条件下的火山作为隐藏参照，只报告，不作判定。

氨分解是五个新反应里唯一一个用 `--atomic` 跑通三尺度全链的反应。

## 4 检验方式

V3 的改动是在看过甲烷化留出值之后定的，所以 V3 在甲烷化上的表现不算验证。检验靠以下三项：

- NH3 合成和甲醇的盲测（手工模型隐藏，对照 21/63 和 26/63）；
- 氨分解三次建模，对照留出 TEA；
- 原子尺度一层的留出对照（见第 3 节）。

另外做一次甲烷化 V3 复跑，只作为诊断，看证据欠账能不能自己发现 H2 进料压力的问题；它不替换 V2 的结果。
