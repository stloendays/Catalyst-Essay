# 开发集与检验集划分、规则通用性、运行账本（2026-11-13 记录，供写论文用）

依据：导师 2026-11-13 口头意见：

- 甲烷化只作为改进依据，丙烷脱氢同样如此；
- 检验靠氨分解和两个盲测，相当于训练集和测试集分开；
- 规则加审查是系统设计的一部分，规则必须通用；
- 每次运行的 token、费用、反应、材料都要记下来，作为原始实验数据。

## 2 规则从哪里来、什么时候冻结

| 规则 | 来源（开发集上看到的问题） | 加入版本 |
|---|---|---|
| 先画流程再算账；逐类过一遍流程清单（进料准备、反应器供热/移热、催化剂再生、产品压缩、分离提纯、循环、热回收、公用工程），每一类要么列出单元，要么写明不需要的理由 | 丙烷脱氢 V1 三次都漏了再生空气加热、产品气压缩、丙烯精馏 | V2 |
| 物理一致性门控：物料和元素平衡、能耗有热力学下限 | 丙烷脱氢 V1 | V2 |
| 压缩功 ≤ 2.5 倍等温最小功；边界进料状态必须与设计基准一致；放热反应器配外购预热要给证据 | 甲烷化 V2：H2 被默认在 1 bar 进装置，放热反应器还配了外购预热 | V3 |
| 单元投资按设备类型做量级检查（USD/kW） | 甲烷化 V2 b1：单位换算错误，投资高 46 倍 | V3 |
| 设计基准 `basis.json`：每股进料的温度、压力、纯度都要有出处，没有出处的标为假设并给出范围 | 甲烷化 V2：H2 进料压力无出处 | V3 |
| 证据欠账：由固定代码做敏感性分析，影响超过 10% 的假设必须补证据，或列为主要不确定性 | 同上 | V3 |
| 独立审查：另一个模型（gpt-5.6-luna）只看交出的流程和数据，按固定清单提问题，不给数字 | Notion 40 提案；甲烷化 V2 | V3 |
| 再生器、加热炉、分离单元能耗为 0 时必须给出实测或已发表的证据 | 丙烷脱氢 V2 诊断：再生能耗记为 0 | V3.1 |
| 统一价格表，AI 只能引用 | 甲烷化 V2 三次之间的成本差主要来自自设价格（H2 一次取 2、一次取 5 USD/kg） | V3.1 |
| 敏感性分析由确定性代码计算，不调用 LLM | 用户 11-13 要求 | V3.1 |
| 原子尺度一层（通用微观动力学求解器、`atomic.py` 合同、三个最优） | 导师要求覆盖原子、实验室、工厂三个最优；与开发集结果无关 | V3 |

A1–A6 只涉及评估端代码、留出隔离和运行保障。AI 收到的建模指令、门控、价格表、留出目标、容差和一致性规则都没有改。每次无效运行的原因和替换关系都记在修订文件和运行账本里：

- 卡死、超出轮数上限的运行判为无效，由新运行替换；
- 判定只看运行是否完成，不看结果好坏。

## 4 规则通用性审查（2026-11-13）

审查了 AI 能看到的全部指令和门控代码：`build_mode.py` 的提示词、`physics_gate.py`、`basis_gate.py`、`atomic_layer.py`、`mkm_solver.py`。

- **规则都按单元类型、热力学和证据类型来写，没有出现任何具体反应、催化剂或工厂的名称和数值。** 具体包括：
  - 流程清单；
  - 物料、元素和能量平衡；
  - 压缩功和预热的上限；
  - 按设备类型的投资量级；
  - 零能耗要求的证据；
  - 设计基准和证据欠账；
  - 审查清单；
  - 原子层合同。
- **微观动力学求解器不含反应数据。** 描述符、基元步骤、标度关系都由 AI 自己选择并给出出处。
- **两张数据表是数据，不是规则，对任何反应都同样适用：**
  - 物性表：NIST 数据，15 个物种；
  - 价格表：53 项，包括大宗原料、公用工程、金属和财务参数。

  新反应如果用到表外物种或原料，按同样的公开来源补数据，不涉及建模选择。
- **审查中注意到两处，写论文时说明：**
  1. 提示词里有一个字段路径示例 `basis.feeds.H2.P_bar`，用的物种名是 H2。它只说明字段怎么写，不含数值。
  2. 价格表里有 3 项和手工模型用的是同一个假设：电价 80 USD/MWh、催化剂载体加制造费 20 USD/kg、固定运维费为投资的 4%/年。在盲测中，这三项经济参数两边相同，差异只来自建模本身。论文中写成"共同的经济基准"。

论文中的表述：AI 自主建模在一套通用规则和独立审查下进行，规则和审查本身是系统设计的一部分。系统并不是让 AI 在没有约束的条件下建模。规则只按单元类型、热力学和证据来写，对任何反应都适用。

## 5 运行账本（原始数据）

`run_ledger.py` 读取每个运行目录，生成：

- `evaluation/run_ledger/RUN_LEDGER.csv`：每次运行一行，包括：
  - 反应、开发集或检验集、建模版本、有效与否及原因；
  - 模型和路由、轮数；
  - 各环节的输入和输出 token（建模、文献抽取、独立审查）；
  - 按 gpt-5.5 标价折算的费用、时长；
  - 论文数、记录数、催化剂数、主要元素、参考工厂、最便宜的催化剂。
- `RUN_STAGES.csv`：每次运行按阶段拆开的明细。
- `RUN_LEDGER.md`：中文汇总。

账本可以随时重跑。全部运行结束后，再生成一次最终版本存档。
